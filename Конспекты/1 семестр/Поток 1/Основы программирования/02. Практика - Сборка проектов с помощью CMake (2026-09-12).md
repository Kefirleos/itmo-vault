## 1. Зачем нужен CMake

**CMake** — это кроссплатформенная мета-система сборки. Она не компилирует код напрямую, а генерирует платформо-специфичные файлы сборки (Ninja, Makefiles для Linux/macOS, Visual Studio Projects для Windows):

```mermaid
flowchart LR
    Source["CMakeLists.txt + C++ Source"] --> CMake["CMake Generator"]
    CMake --> Ninja["Ninja / Makefiles / MSBuild"]
    Ninja --> Clang["Компилятор Clang / GCC / MSVC"]
    Clang --> Bin["Исполняемые бинарники и библиотеки"]
```

---

## 2. Иерархия модулей и структура файлов проекта

Профессиональный проект на C++ организуется в виде дерева каталогов:
```text
my_project/
├── CMakeLists.txt          # Корневой файл конфигурации сборки
├── bin/
│   ├── CMakeLists.txt      # Сборка исполняемого файла (main)
│   └── main.cpp
├── lib/
│   ├── CMakeLists.txt      # Сборка статической/динамической библиотеки
│   ├── calculator.cpp
│   └── calculator.h
└── tests/
    ├── CMakeLists.txt      # Сборка модульных тестов
    └── test_calculator.cpp
```

## 3. Синтаксис и ключевые команды `CMakeLists.txt`

### 3.1. Корневой `CMakeLists.txt`
```cmake
cmake_minimum_required(VERSION 3.20)
project(CalculatorProject VERSION 1.0.0 LANGUAGES CXX)

# Включение стандарта C++20 для всех таргетов
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# Подключение подкаталогов проекта
add_subdirectory(lib)
add_subdirectory(bin)
add_subdirectory(tests)
```

### 3.2. Библиотека: `lib/CMakeLists.txt`
```cmake
# Создание статической библиотеки
add_library(calculator_lib STATIC calculator.cpp)

# Добавление путей к заголовочным файлам для тех, кто линкует библиотеку
target_include_directories(calculator_lib PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
```

### 3.3. Исполняемый файл: `bin/CMakeLists.txt`
```cmake
# Создание бинарного исполняемого файла
add_executable(calc_app main.cpp)

# Линковка библиотеки к приложению
target_link_libraries(calc_app PRIVATE calculator_lib)
```

---

## 4. Области видимости таргетов: `PUBLIC`, `PRIVATE`, `INTERFACE`

- `PRIVATE`: флаги и зависимости нужны **только самому таргету** при компиляции.
- `INTERFACE`: флаги и заголовочные файлы нужны **только тем, кто линкует данный таргет** (характерно для header-only библиотек).
- `PUBLIC`: транзитивно распространяется и на сам таргет, и на всех потребителей.

---

## 5. Сборка из командной строки (Out-of-source Build)

Сборку всегда выполняют в отдельном изолированном каталоге (`build`), чтобы не загрязнять репозиторий артефактами компиляции:

```bash
# 1. Конфигурация проекта в каталоге build
cmake -B build -S .

# 2. Компиляция бинарников
cmake --build build

# 3. Запуск полученного приложения
./build/bin/calc_app
```
