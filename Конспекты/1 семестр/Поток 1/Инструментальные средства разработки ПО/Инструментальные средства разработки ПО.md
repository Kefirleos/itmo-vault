> **Трудоёмкость:** 3 з.е.  
> **Форма итогового контроля:** Дифференцированный зачёт (100 баллов)

## 📊 Структура лабораторных работ

Курс ориентирован на практическое освоение фундаментального инструментария современной программной инженерии. Каждая работа оценивается примерно в **10–12 баллов** и защищается с подробным отчётом:

| № | Тема лабораторной | Инструментарий | Ключевые цели |
|---|---|---|---|
| **Лаб 1** | **Консольный Git** | Git CLI, GitHub | Клонирование, ветвление, коммиты, графы истории (`git log --graph`), анализ изменений. |
| **Лаб 2** | **Документация и ТЗ** | Markdown, PlantUML / Mermaid | Формулировка технического задания (ТЗ), проектирование архитектуры, документирование API. |
| **Лаб 3** | **Плагин для IDE** | JetBrains SDK / VS Code API | Разработка собственного плагина, автоматизация действий разработчика. |
| **Лаб 4** | **Unit-тестирование** | GoogleTest / PyTest | Модульное тестирование, покрытие кода (code coverage), TDD. |
| **Лаб 5** | **CI/CD Автоматизация** | GitHub Actions | Непрерывная интеграция, автоматический запуск тестов, линтинг, сборка артефактов. |

---

## 📝 Регламент оформления отчётов и дедлайнов

> [!tip] Стандарт отчёта по лабораторной работе
> 1. **Пошаговое описание:** каждый этап задания должен быть описан чётко с обоснованием выполняемой команды.
> 2. **Скриншоты и терминальные листинги:** подтверждение успешного выполнения каждого шага (вывод консоли, статус репозитория).
> 3. **Сроки выполнения:** стандартный цикл выполнения одной лабораторной — **2 недели**.
> 4. **Политика использования ИИ:** ИИ допускается как инструмент-ассистент, но студент обязан полностью понимать архитектуру и уметь защитить каждую строчку кода и конфигурации.
