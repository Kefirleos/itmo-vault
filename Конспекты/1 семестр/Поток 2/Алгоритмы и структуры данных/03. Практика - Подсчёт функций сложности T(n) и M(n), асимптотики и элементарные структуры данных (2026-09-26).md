## 📌 Краткое резюме (TL;DR)

1. **Алгоритм плохой**, если он **медленный** (дорогое железо, слабые мобильные устройства, нестабильная сеть, потеря пользователей) или **жрёт память** (не хватает другим программам, данных много). Качество оформления важно для людей, а пользователь видит только скорость и память.
2. **Подсчёт «в пунктах»:**
   - **Память $M(n)$:** переменная — 1 пункт, массив или строка длины $n$ — $n$ пунктов.
   - **Время $T(n)$:** операция (присваивание, сравнение, арифметика) — 1 пункт; цикл — число итераций × стоимость итерации; условие — число логических операций в нём.
3. Если число итераций **зависит от данных**, точную $T(n)$ не вывести. Оценивают **минимум** (лучший случай) и **максимум** (худший): кривая реальной работы лежит между ними, как между асимптотами.
4. **Асимптотика** отбрасывает константы и младшие члены: $T(n) = 2n^2 + 2n + 3 \Rightarrow O(n^2)$.
5. **Свойства $O$:** сумма → максимум, произведение → произведение, константы отбрасываются.
6. **Зачем оценивать:** на $n = 10^7$ алгоритм $n^2$ на машине в 100 раз быстрее работает **больше суток**, а $n \log n$ — **23 секунды**.
7. **Классы:** $O(1)$, $O(\log n)$ (бинпоиск), $O(n)$ (подсчёт вхождений), $O(n \log n)$ (Merge Sort), $O(n^2)$ (пузырёк), $O(n^3)$ (тройки), $O(2^n)$ (подмножества), $O(n!)$ (перестановки).
8. **Элементарные структуры:** массив — «вагон» с пронумерованными местами (доступ по индексу за $O(1)$); массив массивов — «поезд»; `struct` — набор разнотипных характеристик одного объекта; массив структур — «вагон студентов».

## Часть I. Оценка сложности алгоритмов

### 1. Как понять, что реализация не подходит?

**Алгоритм** = вход (значения) → вычисления (код) → выход (значение).

#### 1.1. Качество кода

- **Оформление:** единообразный стиль (стандарт кодирования).
- **Читаемость:** другой программист должен понять реализацию.
- **Сложный код** — длинное неструктурированное «полотно».

Но на кого это влияет? Пользователь **кода не видит**. Плохое оформление мешает **разработчикам**: сложно искать ошибки и разбираться в чужом коде.

#### 1.2. Какой алгоритм плохой — с точки зрения пользователя

| Медленно работает | Много занимает памяти (чаще оперативной) |
|:---|:---|
| Быстрые машины дорогие, у большинства пользователей они недорогие | Не хватает места другим приложениям |
| Мобильные устройства слабее компьютеров | Другие программы начинают работать медленно |
| Сеть может сбоить и быть медленной | Данных бывает очень много, дублирование и хранение в быстрой памяти — проблема |
| Нужен быстрый отклик, иначе теряем пользователей и деньги | — |

### 2. Подсчёт сложности «в пунктах»

#### 2.1. Правила

| По **памяти** $M(n)$ | Пункты |
|:---|:---:|
| 1 переменная | 1 |
| Массив размера $n$ | $n$ |
| Строка длины $n$ | $n$ |

| По **времени** $T(n)$ | Пункты |
|:---|:---:|
| 1 операция: присвоить / сравнить / сложить | 1 |
| 1 итерация цикла из $k$ операций | $k$ |
| Условие из $t$ логических операций и действий | $t$ |

#### 2.2. Пример 1: память и простой цикл

```text
int i, j, n;          // 3 переменные → 3 пункта
int A[100];           // массив из 100 → 100 пунктов
char B[n];            // строка из n   → n пунктов

for i = 1 to n {      // i = 1: 1 пункт; n итераций
    j++;              // 1 пункт
    k = n;            // 1 пункт
}
```

$$
T(n) = \underbrace{1}_{i\,=\,1} + n \cdot \underbrace{2}_{\text{тело}} = 2n + 1.
$$

#### 2.3. Пример 2: цикл `while` с условием

```text
while (A[i] + A[i-1] > 0) {   // условие: A[i], A[i-1], +, > → 3 пункта (по слайду)
    A[i + 1] = A[i];          // 2 пункта
    i = i - 1;                // 2 пункта
}
if (i < 0 && (i/2 = 0))       // 4 пункта: <, &&, /, сравнение
    then j = n;
```

На слайде итерация стоит $3 + 2 + 2 = 7$ пунктов, при $n$ итерациях $T = 7n$. Условие `if` — 4 пункта, из них `i/2 = 0` — 2 операции.

> [!note] Пункты — договорённость
> Сколько «стоит» `A[i+1] = A[i]` — 2 пункта (вычислить индекс и присвоить) или больше (два обращения к памяти) — вопрос соглашения. На асимптотику он не влияет: меняются только константы.

#### 2.4. Пример 3: полный подсчёт $M(n)$ и $T(n)$ (слайд 11)

```text
int i, j, n = 100;            // M: +3          T: +1 (n = 100)
int A[n] = 1;                 // M: +n          T: +n (заполнение)
char B[n];                    // M: +n

for i = 1 to n do             //                T: +1 (i = 1), n итераций по 1
    j++;                      //                T: {+n}

i = n;                        //                T: +1
while (A[i] + A[i-1] > 0) {   //                T: {+3
    A[i + 1] = A[i];          //                    +2
    i = i - 1;                //                    +2
    if (i<0 && (i/2=0)) then j=n;   //              +4+1 = 5} = 12 за итерацию
}                             //                n итераций
```

$$
M(n) = 3 + n + n = 2n + 3, \qquad
T(n) = \underbrace{1 + n}_{\text{объявления}} + \underbrace{1 + n}_{\text{for}} + \underbrace{1 + 12n}_{\text{while}} = 14n + 3.
$$

> [!warning] Расхождение со слайдом
> На слайде итог записан как $T(n) = 14n + 2$ при промежуточной сумме «$12n + 1 + n + n + 1$». Если сложить **все** выписанные в таблице «+1» (за `n = 100`, `i = 1` и `i = n`), получится $14n + 3$. На асимптотику $O(n)$ это не влияет.

#### 2.5. Пример 4: вложенные циклы (слайд 13)

```text
int n = 10;                   // M: 1           T: +1
int A[n];                     // M: +n
int key, i, j;                // M: +3

for i = 0 to n-1 do           //                T: +1, n итераций
    A[j] = i;                 //                T: {+n}   (на слайде опечатка: должно быть A[i])

for i = 0 to n-1 do           //                T: +1, n итераций
    for j = 0 to n-1 do       //                  {+1, n итераций
        A[i] = A[i] + A[j];   //                    {+2}}
```

Внутренний цикл стоит $1 + 2n$, внешний повторяет его $n$ раз:

$$
M(n) = n + 4, \qquad T(n) = n(2n + 1) + 1 + n + 1 + 1 = 2n^2 + 2n + 3.
$$

#### 2.6. Функции сложности — это функции

- $M(n)$ — сложность по памяти, $T(n)$ — по времени; обе зависят от **размера входа** $n$. Размер может стать известен только во время выполнения программы.
- Функция может быть простой: код без циклов и массивов даёт константы, например $M(n) = 3$, $T(n) = 6$.
- Типовые функции: $x^2$, $\log_2 x$, $x \log_2 x$, $x^3$, $a^x$, …
- **$M(n)$ предсказуемее:** она обычно определяется размером входа. **$T(n)$** сильнее зависит от программиста и его «творческого порыва». Дальше под **сложностью алгоритма** по умолчанию понимается **временная**.

#### 2.7. Пример 5: треугольный цикл и арифметическая прогрессия (слайды 17–18)

```text
for i = 1 to n do
    for j = 1 to i do
        A[i] = A[i] + A[j];
```

| Итерация внешнего $i$ | 1 | 2 | 3 | 4 | 5 | $\dots$ | $n$ |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| Итераций внутреннего | 1 | 2 | 3 | 4 | 5 | $\dots$ | $n$ |

Внутренний цикл зависит от внешнего, число его итераций растёт на 1. Всего тел цикла:

$$
T(n) = 1 + 2 + \dots + n = \frac{(1 + n)\,n}{2} = \frac{n^2 + n}{2} = \Theta(n^2).
$$

#### 2.8. Пример 6: когда $T(n)$ зависит от данных (слайды 19–21)

```text
i = N;
while (A[i] + A[i-1] > N) {
    A[i - 1] = A[i];
    i = i - 1;
}
```

Не зная массив `A`, точную функцию времени вывести **невозможно**. Оценивают границы:
- **минимально:** цикл не выполнится ни разу, условие проверится 1 раз — **3 операции**;
- **максимально:** цикл выполнится $N$ раз — порядка **$7N$**.

Реальная $T(n)$ «скачет» между этими границами, а они ведут себя как **асимптоты** (слайд 21).

> [!warning] Ошибки в коде слайдов
> - Объявлено `int n = 10`, а дальше используется `N` — это разные идентификаторы.
> - При `i = N` обращение `A[i]` выходит за границу массива `A[N]` (допустимые индексы `0..N−1`). При $i = 0$ обращение `A[i-1]` тоже выходит за границу. На алгоритмических слайдах это условность, в C++ — **неопределённое поведение**.

### 3. От точной функции к асимптотике

**Порядок роста** описывает, как растёт сложность при увеличении $n$. Записывается в **O-нотации** (от нем. *Ordnung* — порядок): $O(f(n))$.

| $T(n)$ | Порядок роста |
|:---|:---:|
| $2n^2 + 2n + 3$ | $O(n^2)$ |
| $1290n^3 + 12n^2 - 3586$ | $O(n^3)$ |
| $2n^2 \log n + 142n^2 - n$ | $O(n^2 \log n)$ |
| $1290n^3 + 2n^2 \log n - 142n^2 - n + 386$ | $O(n^3)$ |

#### 3.1. Определения

$$
f(n) = O(g(n)) \iff \exists\, c > 0,\ n_0 > 0 : \forall n > n_0 \quad 0 \le f(n) \le c \cdot g(n) \qquad \text{— оценка сверху}
$$
$$
f(n) = \Omega(g(n)) \iff \exists\, c > 0,\ n_0 > 0 : \forall n > n_0 \quad 0 \le c \cdot g(n) \le f(n) \qquad \text{— оценка снизу}
$$
$$
f(n) = \Theta(g(n)) \iff \exists\, c_1, c_2, n_0 > 0 : \forall n > n_0 \quad 0 \le c_2\, g(n) \le f(n) \le c_1\, g(n) \qquad \text{— точная оценка}
$$

#### 3.2. Свойства

Пусть $f_1(n) = O(g_1(n))$, $f_2(n) = O(g_2(n))$. Тогда:

1. **Сумма:** $f_1 + f_2 = O(\max(g_1, g_2))$ — берётся бо́льшая из функций.
2. **Произведение:** $f_1 \cdot f_2 = O(g_1 \cdot g_2)$.
3. **Умножение на константу:** $c \cdot f_1 = O(g_1)$ — константы отбрасываются.
4. **Сложение с константой:** $f_1 + c = O(g_1)$.
5. **Связь оценок:** $f(n) = \Theta(g(n)) \iff f(n) = O(g(n))$ **и** $f(n) = \Omega(g(n))$.

> [!warning] Ошибка на слайде в свойстве 5
> На слайде свойство записано как «$f = \Theta(g) \iff O(g) = \Omega(g)$». Так писать **неверно**: $O(g)$ и $\Omega(g)$ — это **разные множества функций**, и они никогда не равны. Правильно: функция $f$ **принадлежит обоим** множествам, $f \in O(g) \cap \Omega(g)$. Подробно эта ошибка разобрана в шпаргалке к [[04. Практика - Шпаргалка по асимптотике, 26 типовых примеров и задачи на оценку циклов (2026-10-03)|практике 4]].

### 4. Зачем оценивать алгоритмы

#### 4.1. Быстрое железо не спасает от плохой асимптотики

| | Устройство 1 | Устройство 2 |
|:---|:---:|:---:|
| Скорость | $10^9$ оп/с | $10^7$ оп/с (в 100 раз медленнее) |
| Объём данных | $N = 10^7$ | $N = 10^7$ |
| Алгоритм | $n^2$ | $n \log n$ |
| Время | $\dfrac{10^7 \cdot 10^7}{10^9} = 10^5$ с — **больше суток** | $\dfrac{10^7 \cdot \log_2 10^7}{10^7} \approx 23{,}25$ с — **меньше минуты** |

#### 4.2. Таблица роста при $10^6$ операций в секунду

| Сложность \ $n$ | 10 | 20 | 30 | 40 | 50 | 60 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| $n$ | 0,00001 с | 0,00002 с | 0,00003 с | 0,00004 с | 0,00005 с | 0,00006 с |
| $n^2$ | 0,0001 с | 0,0004 с | 0,0009 с | 0,0016 с | 0,0025 с | 0,0036 с |
| $n^3$ | 0,001 с | 0,008 с | 0,027 с | 0,064 с | 0,125 с | 0,216 с |
| $n^5$ | 0,1 с | 3,2 с | 24,3 с | 1,7 мин | 5,2 мин | 13 мин |
| $2^n$ | 0,001 с | 1 с | 17,9 мин | 12,7 дней | 35,7 **лет** | 366 веков |
| $3^n$ | 0,059 с | 58 мин | 6,5 лет | 3855 веков | $2 \cdot 10^8$ веков | $1{,}3 \cdot 10^{13}$ веков |

> [!note] Исправления к таблице слайда
> - $n = 60$, строка $n$: $60 / 10^6 = 0{,}00006$ с (на слайде повторено 0,00005).
> - $2^{10} / 10^6 \approx 0{,}001$ с (на слайде 0,0001).
> - $2^{50} / 10^6 \approx 1{,}13 \cdot 10^9$ с $\approx$ **35,7 лет**, а не веков. Следующее значение, $2^{60}$, действительно $\approx 366$ веков.

#### 4.3. Классы сложности и где они встречаются

| Класс | Пример со слайдов | Почему такая оценка | Подходит для $n$ порядка |
|:---|:---|:---|:---:|
| $O(1)$ | доступ к элементу массива | не зависит от $n$ | любого |
| $O(\log n)$ | **бинарный поиск** | область поиска на каждом шаге сокращается вдвое | любого |
| $O(n)$ | подсчёт чисел, равных $x$ | один проход по массиву | $\sim 10^8$ |
| $O(n \log n)$ | **сортировка слиянием** | $\log n$ уровней деления, на каждом — суммарно $n$ работы | $\sim 5 \cdot 10^7$ |
| $O(n^2)$ | **сортировка пузырьком** | обработка всех пар | $\sim 10^4$ |
| $O(n^3)$ | перебор всех троек | три вложенных прохода | $\sim 500$ |
| $O(2^n)$ | перебор всех подмножеств занятых мест | $2$ варианта на каждое место | $\sim 26$ |
| $O(n!)$ | перебор всех рассадок $n$ человек на $n$ мест | $n!$ перестановок | $\sim 11$ |

#### 4.4. Бинарный поиск — эталон $O(\log n)$

**CLRS-псевдокод** (инвариант: `A[l] < key ≤ A[r]`, где `A[−1] = −∞`, `A[n] = +∞`):

```text
BIN-SEARCH(A, key)
1  l ← −1;  r ← n
2  while l < r − 1
3      m ← ⌊(l + r) / 2⌋
4      if A[m] < key
5          l ← m
6      else r ← m
7  return r          ▷ первая позиция с A[r] ≥ key
```

**C++20:**

```cpp
#include <cstddef>
#include <span>

// Индекс первого элемента >= key (аналог std::lower_bound) в отсортированном массиве
[[nodiscard]] std::size_t LowerBound(std::span<const int> a, int key) noexcept {
    std::ptrdiff_t l = -1;
    std::ptrdiff_t r = static_cast<std::ptrdiff_t>(a.size());
    while (l < r - 1) {                                  // инвариант: a[l] < key <= a[r]
        const std::ptrdiff_t m = l + (r - l) / 2;        // без переполнения (l + r)
        if (a[static_cast<std::size_t>(m)] < key) {
            l = m;
        } else {
            r = m;
        }
    }
    return static_cast<std::size_t>(r);
}
```

Длина отрезка $(l, r)$ каждый раз уменьшается вдвое, поэтому итераций $\lceil \log_2(n + 1) \rceil = O(\log n)$.

## Часть II. Элементарные структуры данных

### 5. Массив: «вагон поезда»

| Вагон | Массив |
|:---|:---|
| Фиксированное число мест | Фиксированный размер `N` |
| Вагон может быть заполнен не полностью | Часть ячеек может быть «пустой» |
| Перевозит один вид «груза» — людей | Все элементы одного **типа** |
| 1 место — 1 пассажир, у каждого свой номер | 1 ячейка — 1 значение, у каждой свой **индекс** |
| Зная номер места, пассажира находим сразу | Доступ по индексу за $O(1)$ |
| Пассажиры могут поменяться местами | Обмен значений |

| Вагон 13 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| пассажир | Анна | Олег | Катя | Петя | Оля | Зина | Коля | Поля | ⟨пусто⟩ |

**Операции над набором данных:**
- **Чтение** по индексу: `Вагон13[7]` → «Коля».
- **Запись** (занять место): `Вагон13[9] = «Валя»`.
- **Удаление** (освободить место): `Вагон13[4] = ⟨пусто⟩`.
- **Перестановка** через временную переменную: `tmp = Вагон13[2]; Вагон13[2] = Вагон13[1]; Вагон13[1] = tmp`.

### 6. Массив и строка в C

```c
int massive[9] = {12, 2, 4, 1, 5, 4, 11, 1, 45};   // тип имя[размер]

// максимум
int max = massive[0];
for (int i = 1; i < 9; i++) {       // ← на слайде i < 10: выход за границу!
    if (massive[i] > max) {
        max = massive[i];
    }
}
```

**Строка в C** — массив символов, оканчивающийся нулевым символом `'\0'`:

```c
char string1[6] = {'H', 'e', 'l', 'l', 'o', '!'};   // массив символов, БЕЗ '\0' — это не строка
char string2[7] = "Hello!";                          // строка: 6 символов + '\0'

for (int i = 0; i < 6; i++) printf("%c", string1[i]);   // вывод по символу
printf("%s", string2);                                   // вывод строки целиком — нужен '\0'
```

`'символ'` — одиночные кавычки, `"текст"` — двойные.

> [!warning] Ошибки в коде слайдов, которые важно не повторить
> 1. **`for (i = 1; i < 10; i++)` при размере 9** — чтение `massive[9]` за границей массива (UB). Граница цикла — размер массива.
> 2. **`scanf("%s", &string1)`** — для массива имя уже является адресом: правильно `scanf("%s", string1)`. А чтение `%s` без ограничения длины может переполнить буфер: безопаснее `scanf("%8s", string1)` для буфера из 9 символов.
> 3. **`fgets(string2, N + 1, stdin)` при `char string2[N]`** — разрешена запись `N + 1` байт в буфер размера `N`, это переполнение. Правильно `fgets(string2, N, stdin)` или `sizeof string2`.
> 4. **`scanf("%d", &string1[i])`** для `char` — неверный спецификатор: нужен `" %c"`.
> 5. **`while (!feof(file)) { fscanf(...); i++; }`** — классическая ошибка: `feof` становится истинным только **после** неудачного чтения, поэтому последняя итерация обрабатывает мусор. Правильно проверять результат чтения: `while (i < N && fscanf(file, "%d", &massive[i]) == 1) i++;`. Отдельно нужно проверить, что `fopen` не вернул `NULL`.

### 7. Массив массивов: «поезд»

- **Поезд** — массив **вагонов**, **вагон** — массив **пассажиров**.
- `Поезд713[i]` — $i$-й вагон, `Поезд713[i][j]` — $j$-й пассажир в $i$-м вагоне.
- Сначала обращаемся к вагону, потом к пассажиру в нём.

```cpp
constexpr int kCars = 9, kSeats = 9;
int train[kCars][kSeats];      // двумерный массив: 9 вагонов по 9 мест
train[0][6] = 42;              // 1-й вагон, 7-е место (индексы с 0)
```

В памяти двумерный массив C/C++ лежит **построчно**: `train[i][j]` находится по смещению $i \cdot \text{kSeats} + j$ от начала.

### 8. Структура `struct`: несколько характеристик одного объекта

У студента ИТМО много характеристик; для задачи выделяют основные:

| Характеристика | Тип |
|:---|:---|
| Имя | `char[50]` |
| Курс | `int` |
| Группа | `char[6]` |
| Возраст | `int` |
| Код ИСУ | `int` |

```c
struct student {
    char name[50];
    int  course;
    char group[6];       // "M3106" — 5 символов + '\0'
    int  age;
    int  code_isu;
};

struct student st = {"Валя", 1, "M3106", 18, 654876};   // инициализация (данные условные)
st.course++;                                             // перевели на следующий курс
strcpy(st.name, "Валентина");                            // ← на слайде st.name = "...": так нельзя!
```

> [!warning] Массиву нельзя присвоить строку
> `st.name = "Валентина";` **не компилируется**: массивы в C не присваиваются. Строку копируют функцией (`strcpy`, лучше `snprintf(st.name, sizeof st.name, "%s", "Валентина")`). В C++ эту проблему снимает поле типа `std::string`.

### 9. Массив структур: «вагон студентов»

```c
#define N 9
struct student students[N];

// чтение (на слайде: scanf("%s", &students[i].name) — снова лишний &)
for (int i = 0; i < N; i++) {
    scanf("%49s", students[i].name);
    scanf("%d", &students[i].course);
    scanf("%d", &students[i].age);
    scanf("%5s", students[i].group);
    scanf("%d", &students[i].code_isu);   // на слайде поле названо .code — опечатка
}

// длина имени каждого студента вручную
for (int i = 0; i < N; i++) {
    int j = 0;
    while (students[i].name[j] != '\0') j++;
    printf("длина имени %s = %d\n", students[i].name, j);
}

// максимальный возраст — типичный шаблон «максимум по полю»
int max_age = students[0].age;
for (int i = 1; i < N; i++) {             // на слайде снова i < 10
    if (students[i].age > max_age) {
        max_age = students[i].age;
    }
}
```

- Сначала обращаемся к элементу массива **по индексу**, затем — к **полю** через точку: `students[i].age`.
- Поиск максимума по полю — шаблон, который «часто используется именно так».

**C++20-вариант** того же поиска:

```cpp
#include <algorithm>
#include <span>
#include <string>

struct Student {
    std::string name;
    int course = 1;
    std::string group;
    int age = 0;
    int code_isu = 0;
};

[[nodiscard]] int MaxAge(std::span<const Student> students) {
    return std::ranges::max(students, {}, &Student::age).age;   // проекция на поле age
}
```

### 10. Сложность операций над массивом

| Операция | Время | Почему |
|:---|:---:|:---|
| Чтение / запись по индексу | $O(1)$ | адрес = начало + индекс × размер элемента |
| Поиск значения | $O(n)$ | перебор |
| Максимум / минимум | $O(n)$ | один проход |
| Вставка в середину со сдвигом | $O(n)$ | сдвиг хвоста |
| Память под массив из $n$ элементов | $M = n$ | — |
