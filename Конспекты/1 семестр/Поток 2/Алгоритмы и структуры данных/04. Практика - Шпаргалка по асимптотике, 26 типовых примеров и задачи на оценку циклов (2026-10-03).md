## 📌 Краткое резюме (TL;DR)

1. **RAM-модель:** простая операция (`+ * − = if call`) и обращение к памяти — 1 шаг; память не ограничена, кэша и диска нет. Модель неточна, но для сравнения алгоритмов работает отлично.
2. **Случай** (лучший, худший, средний) описывает **входные данные**, а **оценка** ($O$, $\Omega$, $\Theta$) — **функцию** затрат в этом случае. Это независимые понятия.
3. **$O(g)$, $\Omega(g)$, $\Theta(g)$ — множества функций.** Запись $f = O(g)$ означает $f \in O(g)$, и «равенства» с $O$ читаются только **слева направо**.
4. **$\Theta$ ⇔ одновременно $O$ и $\Omega$**, но $O(g) \ne \Omega(g)$ как множества.
5. **Как оценивать цикл:** найти, как меняется переменная цикла:
   - $+c$ → $O(n/c) = O(n)$;
   - $\times c$ или $/c$ → $O(\log n)$;
   - условие `i * i <= n` → $O(\sqrt{n})$;
   - вложенные циклы → **произведение**; последовательные → **сумма** (берётся больший член);
   - зависимый внутренний цикл → **сумма ряда** (арифметическая прогрессия, сумма квадратов).
6. **Ловушки:** «вложенный цикл = $O(n^2)$» неверно, если переменная внутреннего цикла **не сбрасывается** (скользящее окно, общий `j`) — тогда **амортизированно** $O(n)$.
7. **$\log(n!) = \Theta(n \log n)$** — оценка сверху и снизу «половиной слагаемых».

## 1. Теоретический минимум

### 1.1. RAM-модель вычислений

Машинно-независимый анализ проводится на гипотетической **RAM-машине** (Random Access Machine):
- каждая **простая** операция (`+`, `*`, `-`, `=`, `if`, `call`) занимает **1** шаг;
- **циклы и подпрограммы** — не простые операции, а последовательности простых;
- каждое **обращение к памяти** — 1 шаг; память неограниченна, **кэша и диска нет**.

Время работы — общее число шагов.

> [!note] Все три допущения неверны для реального компьютера
> Умножение дороже сложения; компилятор и процессор ускоряют циклы; время доступа зависит от уровня иерархии памяти (вспомните [[04. Семинар - Файловый ввод-вывод в стиле C, fgetc, fread и буферизация (2026-09-26)|семинар по буферизации]]). И всё же RAM-модель — **отличный компромисс**: трудно придумать алгоритм, для которого она даст существенно неверный вывод о масштабируемости.

### 1.2. Лучший, худший и средний случаи

Представим график: по оси $OX$ — размер входа $n$, по $OY$ — число шагов. Для каждого $n$ точки разных входов образуют **столбец**.

| Линия | Как строится | Смысл |
|:---|:---|:---|
| **Худший случай** | соединить верхние точки столбцов | максимум шагов для данного $n$ — гарантия |
| **Лучший случай** | соединить нижние точки | минимум шагов, «везение»; ниже не бывает |
| **Средний случай** | соединить средние значения | поведение на случайных данных; полезнее всего на практике, но сложнее всего считается |

> [!important] Не путать
> **Случай** — характеристика **входных данных**. **Оценка** ($O / \Omega / \Theta$) — характеристика **функции**. Можно говорить «худший случай Quick Sort — $\Theta(n^2)$» и «лучший случай Insertion Sort — $\Theta(n)$».

### 1.3. Определения и смысл

Точная функция затрат неудобна: у неё бывают локальные экстремумы, и для её вычисления нужно слишком много информации. Её «зажимают» гладкими границами:

$$
\begin{aligned}
f(n) = O(g(n)) &\iff \exists\, c, n_0 > 0 : \forall n \ge n_0 \;\; 0 \le f(n) \le c \cdot g(n) &&\text{(не быстрее } g\text{)}\\
f(n) = \Omega(g(n)) &\iff \exists\, c, n_0 > 0 : \forall n \ge n_0 \;\; 0 \le c \cdot g(n) \le f(n) &&\text{(не медленнее } g\text{)}\\
f(n) = \Theta(g(n)) &\iff \exists\, c_1, c_2, n_0 > 0 : \forall n \ge n_0 \;\; 0 \le c_2\, g(n) \le f(n) \le c_1\, g(n) &&\text{(того же порядка)}
\end{aligned}
$$

**Пример.** $\frac{1}{2}n^2 + n = O(n^2)$: при $n \ge 1$
$$
\tfrac{1}{2}n^2 + n \le \tfrac{1}{2}n^2 + n^2 = \tfrac{3}{2}n^2, \qquad c = \tfrac{3}{2},\; n_0 = 1.
$$

$O$ даёт лишь **верхнюю границу**, а не точный порядок. Точную оценку $\Theta$ получают не всегда: она может быть неизвестна (доказана только верхняя граница) или вовсе не существовать, если функция «прыгает» между разными порядками.

### 1.4. $O(g)$ — множество, а не функция

Корректно писать $f(n) \in O(g(n))$. Запись со знаком равенства — исторически сложившееся **злоупотребление обозначениями**, удобное в выкладках:

$$
T(n) = 2T(n/2) + O(n) \quad \text{означает} \quad \exists f \in O(n) : T(n) = 2T(n/2) + f(n).
$$

> [!warning] Ошибка «$\Theta \iff O = \Omega$»
> Утверждение «$f = \Theta(g) \iff O(g) = \Omega(g)$» **абсурдно**: $O(g)$ и $\Omega(g)$ — принципиально разные множества. Верно другое: **конкретная** $f$ лежит в **пересечении** $O(g) \cap \Omega(g)$:
> $$f = \Theta(g) \iff f \in O(g) \ \text{и}\ f \in \Omega(g).$$
> Из того, что один элемент лежит в обоих множествах, их равенство не следует.

### 1.5. Правила работы с $O$

$$
f = O(f), \quad c \cdot O(f) = O(f), \quad O(O(f)) = O(f), \quad O(f)\,O(g) = O(fg), \quad O(fg) = f\,O(g).
$$

Все они **несимметричны** и читаются **только слева направо**. Если читать их как обычные равенства, получится абсурд: $n^2 \in O(n^2)$ и $n \in O(n^2)$, но из «$O(n^2) = n^2$» и «$O(n^2) = n$» не следует $n^2 = n$.

### 1.6. Скорость роста при $10^9$ операций в секунду (по Скиене)

Из таблицы роста следуют практические выводы:
- при $n = 10$ все алгоритмы работают примерно одинаково;
- **$n!$** бесполезен уже при $n \ge 20$;
- **$2^n$** непрактичен при $n > 40$;
- **$n^2$** нормален до $n \approx 10^4$, а при $n > 10^6$, скорее всего, бесполезен;
- **линейные и $n \log n$** обрабатывают миллиард элементов;
- **$O(\lg n)$** справляется с любым мыслимым объёмом.

Даже без учёта констант асимптотика даёт верное представление о том, для каких $n$ алгоритм годится.

### 1.7. Точная оценка на примере: $\log(n!) = \Theta(n \log n)$

```cpp
void Func(int n) {
    for (int i = 0; i <= n; ++i) {
        int y = i;
        while (y > 1) {
            y /= 2;          // ~log2(i) итераций
        }
    }
}
```

Сумма итераций внутреннего цикла: $\log 1 + \log 2 + \dots + \log n = \log(n!)$. С $O(\log(n!))$ неудобно работать: как сравнить её с $O(n^2)$? Найдём $\Theta$.

**Сверху:** каждое слагаемое $\le \log n$:
$$
f(n) \le n \log n \implies f(n) = O(n \log n).
$$

**Снизу:** отбросим первую половину слагаемых, а каждое из оставшихся (от $\frac{n}{2}$ до $n$) оценим снизу через $\log \frac{n}{2}$:
$$
f(n) \ge \sum_{k=n/2}^{n} \log k \ge \frac{n}{2} \log \frac{n}{2} = \frac{n}{2}\log n - \frac{n}{2}\log 2.
$$
При $n \ge 4$ выполнено $\log 2 \le \frac{1}{2}\log n$, поэтому $\frac{n}{2}\log 2 \le \frac{n}{4}\log n$ и
$$
f(n) \ge \frac{n}{2}\log n - \frac{n}{4}\log n = \frac{1}{4}\, n \log n \implies f(n) = \Omega(n \log n).
$$

Итого $f(n) = \Theta(n \log n)$. Это та же оценка, что даёт нижнюю границу $\Omega(n \log n)$ для сортировок сравнениями ([[02. Лекция - Линейные сортировки (Counting, Radix, Bucket) и нижняя оценка сравнений (2026-09-19)|лекция 2]]).

## 2. 26 типовых примеров

### 2.1. Константное время $O(1)$

| № | Код | Почему $O(1)$ |
|:---:|:---|:---|
| 1 | `int res = n * 2 + 5; return res;` | время не зависит от величины $n$ |
| 2 | `return arr[index];` | доступ по адресу «начало + смещение» |
| 3 | `return n * (n + 1) / 2;` | формула суммы прогрессии вместо цикла |

### 2.2. Логарифмическое время $O(\log n)$

**Пример 4.** Деление пополам:

```cpp
int Func(int n) {
    int count = 0;
    while (n > 0) { ++count; n /= 2; }
    return count;
}
```

Значения: $x_k = \left\lfloor \frac{n_0}{2^k} \right\rfloor$. Трассировка для $n_0 = 100$:

| $k$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| $x_k$ | 50 | 25 | 12 | 6 | 3 | 1 | 0 |

Цикл останавливается, когда $2^k > n_0$:
$$
k \ln 2 > \ln n_0 \implies k > \log_2 n_0, \qquad k = \lfloor \log_2 n_0 \rfloor + 1 = 7 \text{ при } n_0 = 100.
$$
Поскольку $\log_2 n = \frac{\ln n}{\ln 2}$ и $\frac{1}{\ln 2}$ — константа, **основание логарифма в асимптотике не пишут**.

| № | Код | Итераций | Оценка |
|:---:|:---|:---|:---:|
| 5 | `for (int i = 1; i < n; i *= 2)` | $\lceil \log_2 n \rceil$ (1, 2, 4, 8, …) | $O(\log n)$ |
| 6 | `while (n > 1) n /= 3;` | $\log_3 n = \frac{\log_2 n}{\log_2 3}$ | $O(\log n)$ |

### 2.3. Квадратный корень $O(\sqrt{n})$

| № | Код | Анализ | Оценка |
|:---:|:---|:---|:---:|
| 7 | `for (int i = 1; i * i <= n; ++i)` | $i \le \sqrt{n}$ → ровно $\lfloor \sqrt{n} \rfloor$ итераций | $O(\sqrt{n})$ |
| 8 | `int i = 2; while (i * i < n) i += 2;` | шаг 2 вдвое уменьшает число итераций: $\frac{1}{2}\sqrt{n}$ | $O(\sqrt{n})$ |

> [!tip] Где встречается $\sqrt{n}$
> Проверка числа на простоту перебором делителей до $\sqrt{n}$, sqrt-декомпозиция.

### 2.4. Линейное время $O(n)$

| № | Код | Анализ | Оценка |
|:---:|:---|:---|:---:|
| 9 | `for (i = 0; i < size; ++i) sum += arr[i];` | $n$ итераций | $O(n)$ |
| 10 | `for (i = 0; i < n; i += 5)` | $\lceil n/5 \rceil$ итераций | $O(\frac{1}{5} n) = O(n)$ |
| 11 | два **последовательных** цикла по $n$ | $O(n) + O(n) = O(2n)$ | $O(n)$ |

### 2.5. Линейно-логарифмическое время $O(n \log n)$

| № | Структура | Анализ |
|:---:|:---|:---|
| 12 | внешний `i < n` (шаг +1), внутренний `j *= 2` до $n$ | $O(n) \cdot O(\log n) = O(n \log n)$ |
| 13 | внешний `i *= 2` до $n$, внутренний `j < n` | $O(\log n) \cdot O(n) = O(n \log n)$ |

Порядок вложенности не важен: умножение коммутативно.

### 2.6. Полуторная степень $O(n\sqrt{n})$

| № | Структура | Анализ |
|:---:|:---|:---|
| 14 | внешний до $n$, внутренний `j * j <= n` | $O(n) \cdot O(\sqrt{n}) = O(n^{3/2})$ |
| 15 | внешний `i * i <= n`, внутренний до $n$ | $O(\sqrt{n}) \cdot O(n) = O(n^{3/2})$ |

### 2.7. Квадратичное время $O(n^2)$

**Пример 16:** два вложенных цикла по $n$ → $O(n) \cdot O(n) = O(n^2)$.

**Пример 17: зависимый внутренний цикл** (`for j = i; j < n`):

| $i$ | 0 | 1 | 2 | $\dots$ | $n-1$ |
|:---|:---:|:---:|:---:|:---:|:---:|
| итераций $j$ | $n$ | $n-1$ | $n-2$ | $\dots$ | 1 |

$$
S_n = \frac{(1 + n)\, n}{2} = \frac{n^2}{2} + \frac{n}{2} = O(n^2).
$$

**Пример 18:** обход матрицы $n \times n$ — каждую из $n^2$ ячеек нужно посетить: $O(n^2)$.

> [!tip] «Вдвое меньше» — это всё ещё $n^2$
> Зависимый цикл делает **половину** работы полного двойного цикла, но асимптотика та же: константа $\frac{1}{2}$ отбрасывается.

### 2.8. Кубическое время $O(n^3)$

**Пример 19:** три вложенных цикла по $n$ → $O(n^3)$.

**Пример 20: трижды зависимые циклы** (`j < i`, `k < j`):

```cpp
for (int i = 0; i < n; ++i)
    for (int j = 0; j < i; ++j)
        for (int k = 0; k < j; ++k) { /* тело */ }
```

Внутренний цикл даёт $j$ итераций. Сумма по среднему:
$$
\sum_{j=0}^{i-1} j = \frac{i(i-1)}{2} = \frac{1}{2}i^2 - \frac{1}{2}i.
$$
По внешнему, используя $\sum_{i=0}^{n-1} i^2 = \frac{(n-1)n(2n-1)}{6}$ (доказывается индукцией) и $\sum_{i=0}^{n-1} i = \frac{n^2 - n}{2}$:
$$
\frac{1}{2}\left(\frac{(n-1)n(2n-1)}{6} - \frac{n^2 - n}{2}\right) = \frac{1}{6}n^3 - \frac{1}{2}n^2 + \frac{1}{3}n = O(n^3).
$$

> [!tip] Проверка через комбинаторику 📎
> Тело выполняется для каждой тройки $k < j < i$, т. е. ровно $\binom{n}{3} = \frac{n(n-1)(n-2)}{6} = \frac{n^3 - 3n^2 + 2n}{6}$ раз — та же формула.

### 2.9. Функции нескольких переменных

| № | Структура | Оценка |
|:---:|:---|:---:|
| 21 | цикл до $a$, **затем** цикл до $b$ | $O(a) + O(b) = O(a + b)$ |
| 22 | цикл до $a$, **внутри** цикл до $b$ | $O(a) \cdot O(b) = O(a \cdot b)$ |

Независимые параметры **нельзя** сводить к одному: $O(a + b) \ne O(a)$, пока неизвестно соотношение $a$ и $b$ (например, $V$ и $E$ в графах).

### 2.10. Скользящее окно — ловушка вложенности

**Пример 23:**

```cpp
int right = 0;
for (int left = 0; left < n; ++left) {
    while (right < n && right < left + 5) {
        ++right;
    }
}
```

> [!important] Не $O(n^2)$, а $O(n)$
> Циклы вложены, но переменная `right` **никогда не сбрасывается** и только растёт. За **всё время работы** она увеличится не более $n$ раз. Суммарная работа внутреннего цикла — $O(n)$ на все итерации внешнего, плюс $O(n)$ от внешнего: итого **$O(n)$**. Так оценивается метод **двух указателей**.

### 2.11. Простая рекурсия

| № | Код | Глубина / вызовов | Оценка |
|:---:|:---|:---|:---:|
| 24 | `f(n) → f(n − 1)` | цепочка из $n$ вызовов; глубина стека $n$ | $O(n)$ |
| 25 | `f(n) → f(n / 2)` | $\log_2 n$ вызовов — рекурсивный аналог `while (n > 0) n /= 2` | $O(\log n)$ |
| 26 | цикл до $n$, затем `f(n − 1)` | $n + (n-1) + \dots + 1$ | $O(n^2)$ |

> [!tip] Рекуррентные соотношения
> Пример 26: $T(n) = T(n - 1) + n \Rightarrow \Theta(n^2)$. Для рекурсий «разделяй и властвуй» вида $T(n) = aT(n/b) + f(n)$ используется мастер-теорема ([[02. Практика - Мастер-теорема, стабильность сортировок и псевдокод (2026-09-19)|практика 2]]).

## 4. Задачи на самопроверку (с проверенными ответами)

> [!example] Задача 1. Два последовательных цикла по $n$
> $O(n) + O(n) = O(2n) = $ **$O(n)$**.

> [!example] Задача 2. `for (int i = 0; i < n / 2; i *= 2)`
> **Ответ шпаргалки:** $O(\log \frac{n}{2}) = O(\log n)$.
>
> ⚠️ **В коде ошибка:** при `i = 0` умножение `i *= 2` оставляет `i = 0`, и цикл **бесконечен** (при $n \ge 2$). Подразумевалось `int i = 1`: тогда итераций $\log_2 \frac{n}{2} = \log_2 n - 1$, т. е. **$O(\log n)$**.

> [!example] Задача 3. `while (i < n) i *= 5;`, затем цикл до $n$
> $O(\log n) + O(n) = $ **$O(n)$**.

> [!example] Задача 4. Общий `j` во вложенном `while`
> ```cpp
> int j = 0;
> for (int i = 0; i < n / 2; ++i) {
>     while (j < n) {
>         j += 1;
>         for (int k = 0; k < n / 2; ++k) { /* ... */ }
>     }
> }
> ```
> **Ответ шпаргалки:** $O(n^3)$ — ⚠️ **неверно.**
>
> **Правильно: $O(n^2)$.** Переменная `j` объявлена **вне** внешнего цикла и **не сбрасывается**. На первой итерации внешнего цикла `while` выполнится $n$ раз, и каждый раз внутренний `for` сделает $n/2$ шагов: всего $n \cdot \frac{n}{2} = \frac{n^2}{2}$. На всех следующих итерациях внешнего цикла `j == n`, и `while` не выполняется ни разу. Итого $\frac{n^2}{2} + \frac{n}{2} = O(n^2)$. Это та же ловушка, что в примере 23 «скользящее окно».

> [!example] Задача 5. `while (i < n) { i *= 3; for (j = 1; j < n; j *= 2) }`
> $O(\log n) \cdot O(\log n) = $ **$O(\log^2 n)$**.

> [!example] Задача 6. Двойной цикл по $n$, внутри `k *= 2` до $\sqrt{n}$
> $O(n^2 \log \sqrt{n}) = O(\frac{1}{2} n^2 \log n) = $ **$O(n^2 \log n)$**.

> [!example] Задача 7. Двойной цикл по $n/4$
> $O\left(\left(\frac{n}{4}\right)^2\right) = O\left(\frac{n^2}{16}\right) = $ **$O(n^2)$**.

> [!example] Задача 8. `for (i = 0; i < sqrt(n); ++i)`
> **$O(\sqrt{n})$**. 📎 Вызов `sqrt(n)` в условии считается на каждой итерации; лучше вычислить его один раз до цикла.

> [!example] Задача 9. Внутренний `j < i`
> $\frac{n(n-1)}{2} = $ **$O(n^2)$**.

> [!example] Задача 10. `i *= 3` снаружи, `j *= 2` до `i` внутри
> Внешний цикл делает $t \approx \log_3 n$ шагов, на шаге $t$ значение $i \approx 2 \cdot 3^t$, и внутренний делает $\log_2 i \approx t \log_2 3$ шагов. Сумма $\sum_{t=1}^{\log_3 n} t \cdot \log_2 3 = O(\log^2 n)$: **$O(\log n \cdot \log n)$**.

> [!example] Задача 11. Цикл до $n$ + `k *= 3` до $n$ + двойной цикл $n \times \frac{n}{3}$
> $O(n + \log n + n^2) = $ **$O(n^2)$** — по правилу суммы остаётся старший член.

> [!example] Задача 12. `for (j = 0; j < (1 << i); ++j)` внутри цикла до $n$
> $\sum_{i=0}^{n-1} 2^i = 2^n - 1 = $ **$O(2^n)$** — экспоненциальная сложность.

## 5. Чек-лист оценки сложности

> [!important] Алгоритм анализа
> 1. Определить **размер входа** (один параметр $n$ или несколько: $a$, $b$, $V$, $E$).
> 2. Для каждого цикла понять, **как меняется переменная** и **когда цикл остановится**.
> 3. Вложенные — **перемножить**, последовательные — **сложить** и оставить старший член.
> 4. Если внутренний цикл зависит от внешнего — посчитать **сумму ряда**.
> 5. Если переменная внутреннего цикла **не сбрасывается** — оценивать **суммарно** за всё время (амортизированно).
> 6. Для рекурсии — записать **рекуррентное соотношение**.
> 7. Отбросить константы и младшие члены.

> [!warning] Типичные ошибки
> - Считать любой двойной цикл $O(n^2)$ (задача 4, пример 23).
> - Забывать, что `i *= 2` от `i = 0` не сдвигается с нуля (задача 2).
> - Сводить $O(a + b)$ к $O(n)$ без знания связи параметров.
> - Писать «$O(g) = \Omega(g)$» вместо «$f \in O(g) \cap \Omega(g)$».
