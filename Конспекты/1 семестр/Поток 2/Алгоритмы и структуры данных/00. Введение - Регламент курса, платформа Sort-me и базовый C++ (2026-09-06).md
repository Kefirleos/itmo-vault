## 1. 🎯 Организация курса и стратегия сдачи на «Отлично» (5A)

### Главные особенности курса:
1. **Экзамен не повышает оценку выше 3E (максимум 60 баллов)!**
   - На экзамен в сессию выходят **только** студенты с 40–59 баллами, сдавшие теорминимум.
   - Студенты с баллом $\ge 60$ получают заслуженную оценку (3D, 3E, 4C, 4B, 5A) **автоматом**.
   - Оценки «4» и «5» зарабатываются **исключительно регулярной работой в течение семестра**.
2. **54 балла за лабораторные — основа всего рейтинга:**
   - Каждая лаба открывается на платформе `sort-me.org` на **2 недели**.
   - Формула перевода: $\text{Баллы} = 54 \times \frac{S}{N}$.
   - После закрытия дедлайна на Sort-me досылать задачи нельзя.
3. **Очная устная защита:**
   - Получить зеленый вердикт `Accepted` недостаточно. Лабу необходимо лично защитить практику (для группы **G** — Анастасия Забашта).
   - На защите проверяется: идея алгоритма, расчет сложности по времени и памяти, пошаговая логика кода, модификация кода под измененное условие.
4. **Двусторонняя Бан-Машина:**
   - Любое совпадение кода между студентами аннулирует баллы за лабу **обоим студентам**.
   - Репозитории на GitHub/GitLab должны быть строго приватными.
5. **Теорминимум — жесткая отсечка:**
   - Проводится в декабре (10 случайных вопросов по всем темам).
   - Порог сдачи теорминимума: **8 баллов**.
   - Если теормин не сдан со 2-й попытки $\implies$ рейтинг фиксируется на $\le 59$ баллах, студент отправляется на допсессию!

## 2. 🧪 Платформа Sort-me.org и вердикты тестирования

Все решения проверяются на скрытом пуле автоматических тестов.

### 📋 Справочник вердиктов:

| Вердикт | Англ. | Описание | Типичная причина и что делать |
| :--- | :---: | :--- | :--- |
| **Полное решение** | `AC` | Программа выдала верные ответы на всех тестах в пределах лимитов времени и памяти. | Зачет! Готовиться к устной защите кода. |
| **Неправильный ответ** | `WA` | На одном из тестов программа вывела неверный результат. | Граничные случаи ($n=0, n=1$), одинаковые элементы, переполнение типов, неверная логика алгоритма. |
| **Превышено время** | `TL` | Программа работала дольше отведенного лимита (обычно 1.0–2.0 сек). | Неоптимальная асимптотика ($O(n^2)$ вместо $O(n \log n)$), медленный I/O (`std::endl`), зацикливание (`while (l < r)`). |
| **Превышена память** | `ML` | Расход памяти превысил лимит (например, 256 МБ). | Слишком большой статический/динамический массив, утечка памяти (`new` без `delete`), бесконечная рекурсия. |
| **Ошибка выполнения** | `RE` | Аварийное завершение с ненулевым кодом (`exit code != 0`). | Выход за границы массива (`arr[i]`, где $i \ge n$), деление на ноль, разыменование нулевого указателя (`nullptr`). |
| **Ошибка компиляции** | `CE` | Код не смог скомпилироваться на сервере. | Синтаксическая ошибка, не подключен заголовочный файл, неверно выбран стандарт языка в системе. |
| **Неправильный формат** | `PE` | Ответ верен по сути, но нарушен формат вывода. | Лишние пробелы, отсутствует перевод строки `\n`, вставлены лишние фразы вроде `"Введите число N:"`. |

## 3. 💻 Базовый шаблон решения на C++ с быстрым I/O

Для успешного прохождения тестов по времени на платформе `sort-me.org` обязательно используйте ускорение стандартных потоков:

```cpp
#include <iostream>
#include <vector>
#include <cstdint>
#include <iomanip>

void solve() {
    int n;
    if (!(std::cin >> n)) return;

    // ВНИМАНИЕ: Для сумм и произведений всегда используем int64_t (long long),
    // чтобы избежать UB при знаковом переполнении 32-битного int!
    int64_t total_sum = 0;
    std::vector<int64_t> a(n);

    for (int i = 0; i < n; ++i) {
        std::cin >> a[i];
        total_sum += a[i];
    }

    // Пример вывода вещественного числа с фиксированной точностью:
    double average = static_cast<double>(total_sum) / n;
    std::cout << std::fixed << std::setprecision(6) << average << '\n';
}

int main() {
    // 1. Отключаем синхронизацию потоков C++ (cin/cout) со стандартными потоками C (scanf/printf)
    std::ios::sync_with_stdio(false);

    // 2. Отвязываем cin от cout: cin не сбрасывает буфер cout перед каждым чтением
    std::cin.tie(nullptr);

    solve();

    return 0;
}
```

> [!caution] std::endl vs '\n'
> Никогда не используйте `std::endl` в цикле вывода!
> `std::endl` делает две вещи:
> 1. Вставляет символ переноса строки `\n`.
> 2. **Принудительно вызывает `flush()`**, заставляя операционную систему немедленно сбрасывать буфер на диск или в консоль.
> При выводе $10^5$ чисел `std::endl` выполнит $10^5$ системных вызовов, превращая $O(n)$ решение в гарантированный **Time Limit Exceeded (TL)**. Используйте только `std::cout << '\n';`.

## 4. 📐 Математический аппарат асимптотического анализа

Для формального сравнения эффективности алгоритмов независимо от вычислительной машины и тактовой частоты процессора используется асимптотический анализ порядка роста функций при $n \to \infty$.

### 1. «О»-большое (Верхняя асимптотическая оценка, $O$)
Описывает гарантированное поведение алгоритма **в худшем случае** (сверху):
$$f(n) = O(g(n)) \iff \exists c > 0, \exists n_0 \in \mathbb{N} : \forall n \ge n_0 \quad 0 \le f(n) \le c \cdot g(n)$$

*Смысл:* Начиная с некоторого размера входа $n_0$, функция $f(n)$ растет не быстрее, чем функция $g(n)$, умноженная на постоянный множитель $c$.

### 2. «Омега»-большое (Нижняя асимптотическая оценка, $\Omega$)
Описывает поведение алгоритма **снизу**:
$$f(n) = \Omega(g(n)) \iff \exists c > 0, \exists n_0 \in \mathbb{N} : \forall n \ge n_0 \quad 0 \le c \cdot g(n) \le f(n)$$

*Смысл:* Алгоритм требует как минимум порядка $g(n)$ операций даже в лучшем/наиболее благоприятном сценарии.

### 3. «Тета»-большое (Точная асимптотическая оценка, $\Theta$)
Описывает порядок роста, сжатый между двумя константами:
$$f(n) = \Theta(g(n)) \iff \exists c_1, c_2 > 0, \exists n_0 \in \mathbb{N} : \forall n \ge n_0 \quad 0 \le c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$$

> [!important] Теорема о связи $O$, $\Omega$ и $\Theta$
> $$f(n) = \Theta(g(n)) \iff \Big(f(n) = O(g(n)) \;\land\; f(n) = \Omega(g(n))\Big)$$

## 5. 📊 Иерархия основных классов асимптотической сложности

В алгоритмическом анализе функции упорядочиваются по скорости их предельного роста:

$$O(1) \subset O(\log \log n) \subset O(\log n) \subset O(\sqrt{n}) \subset O(n) \subset O(n \log n) \subset O(n^2) \subset O(n^3) \subset O(2^n) \subset O(n!)$$

| Сложность | Название | Примеры алгоритмов | Допустимый $n$ за 1.0 сек ($10^8$ оп.) |
| :---: | :--- | :--- | :---: |
| $O(1)$ | Константная | Доступ к элементу массива по индексу, push в стек | Любой ($10^{18}$) |
| $O(\log n)$ | Логарифмическая | Бинарный поиск в отсортированном массиве, алгоритм Евклида | $10^{18}$ |
| $O(\sqrt{n})$ | Корневая | Проверка числа на простоту, корневая декомпозиция | $10^{12} - 10^{14}$ |
| $O(n)$ | Линейная | Линейный поиск, Counting Sort, сифтинг кучи за линию | $10^7 - 10^8$ |
| $O(n \log n)$ | Квазилинейная | Merge Sort, Quick Sort (в среднем), HeapSort | $10^5 - 10^6$ |
| $O(n^2)$ | Квадратичная | Insertion Sort, Bubble Sort, матричное сложение | $5\,000 - 10\,000$ |
| $O(n^3)$ | Кубическая | Классическое умножение матриц, алгоритм Флойда-Уоршалла | $300 - 500$ |
| $O(2^n)$ | Экспоненциальная | Перебор всех подмножеств, задача коммивояжера | $20 - 25$ |
| $O(n!)$ | Факториальная | Перебор всех перестановок | $10 - 11$ |

## 6. 🛠️ Алгебра свойств $O$-символики

1. **Правило сумм (доминирование):**
   $$O(f(n)) + O(g(n)) = O(\max(f(n), g(n)))$$
   *Пример:* $O(n^2) + O(n \log n) + O(100n) = O(n^2)$.
2. **Правило произведений:**
   $$O(f(n)) \cdot O(g(n)) = O(f(n) \cdot g(n))$$
   *Пример:* Внешний цикл на $n$ итераций с внутренним бинарным поиском за $O(\log n)$ дает $O(n \log n)$.
3. **Поглощение констант:**
   $$c \cdot O(f(n)) = O(f(n)) \quad (\text{для любой постоянной } c > 0)$$
   *Пример:* $1000 n = O(n)$, $0.001 n^2 = O(n^2)$.
4. **Транзитивность:**
   $$f(n) = O(g(n)) \;\land\; g(n) = O(h(n)) \implies f(n) = O(h(n))$$
