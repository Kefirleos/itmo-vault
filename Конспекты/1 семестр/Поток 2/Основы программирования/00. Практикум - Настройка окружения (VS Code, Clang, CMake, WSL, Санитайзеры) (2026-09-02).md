## 1. Необходимый инструментарий

Для выполнения всех 5 лабораторных работ семестра вам понадобятся:
- **Компилятор C++:** `clang` (версии $\ge 16$ с поддержкой стандарта C++20).
- **Система сборки:** `cmake` (версии $\ge 3.20$) и генератор `ninja` (для быстрой параллельной сборки).
- **Отладчик:** `lldb` (или `gdb`).
- **Инструменты качества кода:** `clang-format` и `clang-tidy`.
- **Редактор:** Visual Studio Code.
- **Система контроля версий:** `git`.

## 2. Настройка под Windows (рекомендуемый путь через WSL)

Под Windows наилучший и наиболее приближенный к тестирующей системе курса путь — использование **WSL (Windows Subsystem for Linux)**. Это дает полноценное ядро Linux внутри Windows без падения производительности и проблем с путями.

### Шаг 1: Установка WSL Ubuntu
Откройте PowerShell от имени администратора и выполните:
```powershell
wsl --install -d Ubuntu
```
После перезагрузки компьютера задайте имя пользователя и пароль в открывшемся терминале Ubuntu.

### Шаг 2: Установка компилятора и утилит в Ubuntu
В терминале WSL выполните обновление репозиториев и установку пакетов:
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y build-essential clang lldb cmake ninja-build git clang-format clang-tidy
```

Проверьте установленные версии:
```bash
clang++ --version
cmake --version
```

### Шаг 3: Связка VS Code и WSL
1. Установите **Visual Studio Code** в Windows.
2. В VS Code перейдите во вкладку расширений (`Ctrl + Shift + X`) и установите расширение **WSL** (ID: `ms-vscode-remote.remote-wsl`).
3. Нажмите зеленую кнопку удаленного подключения в левом нижнем углу VS Code $\to$ выберите **«Connect to WSL»** (или введите в терминале WSL команду `code .`).
4. В левом нижнем углу появится индикатор `WSL: Ubuntu`. Все файлы и терминал теперь работают внутри Linux!

> [!tip] Где лежат файлы Windows в WSL?
> Все ваши диски Windows смонтированы по пути `/mnt/`:
> - Диск `C:\` $\to$ `/mnt/c/`
> - Диск `D:\` $\to$ `/mnt/d/`
> Однако для максимальной скорости компиляции рекомендуется хранить проекты в домашней директории WSL: `~/projects/lab1`.

## 3. Настройка под Linux

Нативно в дистрибутивах Linux все инструменты ставятся одной командой менеджера пакетов:

**Ubuntu / Debian:**
```bash
sudo apt update
sudo apt install -y clang lldb cmake ninja-build git clang-format clang-tidy
```

**Arch Linux:**
```bash
sudo pacman -S clang lldb cmake ninja git
```

**Fedora:**
```bash
sudo dnf install -y clang lldb cmake ninja-build git clang-tools-extra
```

## 4. Настройка под macOS

1. Установите консольные утилиты Xcode:
   ```bash
   xcode-select --install
   ```
2. Установите менеджер пакетов Homebrew ([brew.sh](https://brew.sh/)):
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```
3. Установите актуальный Clang, CMake, Ninja и инструменты форматирования:
   ```bash
   brew install llvm cmake ninja clang-format
   ```

## 5. Рекомендуемые расширения VS Code

Установите следующие расширения внутри VS Code (если используете WSL — установите их внутри среды WSL):

1. **clangd** (от *LLVM*) — мощный языковой сервер C++, мгновенная автодополнение, поиск определений и предупреждения на лету.  
   *(Примечание: при использовании clangd рекомендуется отключить IntelliSense в стандартном плагине C/C++, чтобы они не конфликтовали).*
2. **CMake Tools** (от *Microsoft*) — интеграция CMake, визуальный выбор компилятора (Kit), кнопка сборки (Build) и отладки (Debug) в один клик в нижней панели.
3. **CodeLLDB** (от *Vadim Chugunov*) — лучший отладчик для C/C++ под LLVM, поддержка точек останова, инспекции переменных и выражений.
4. **Git Graph** — наглядная визуализация веток Git и коммитов.

## 6. Создание эталонного проекта на CMake и запуск

> [!example] Минимальная эталонная структура проекта
> - 📁 `my_project/`
>   - 📄 `CMakeLists.txt`
>   - 📄 `.clang-format`
>   - 📁 `src/`
>     - 📄 `main.cpp`

### Файл `src/main.cpp`:
```cpp
#include <iostream>

int main() {
    std::cout << "Hello from ITMO C++ Course!\n";
    return 0;
}
```

### Файл `CMakeLists.txt`:
```cmake
cmake_minimum_required(VERSION 3.20)
project(itmo_lab LANGUAGES CXX)

# Требуем современный стандарт C++20
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON) # Генерирует compile_commands.json для clangd

# Флаги строгой проверки компилятора:
if (CMAKE_CXX_COMPILER_ID MATCHES "Clang|GNU")
    add_compile_options(-Wall -Wextra -Wpedantic -Werror -Wshadow)
endif()

add_executable(my_program src/main.cpp)
```

### Сборка и запуск через терминал:
```bash
# Конфигурация проекта (генерация файлов сборки):
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug

# Компиляция:
cmake --build build

# Запуск программы:
./build/my_program
```

## 7. Конфигурация `.clang-format` (Google Code Style)

Положите файл `.clang-format` в корень вашего репозитория:
```yaml
BasedOnStyle: Google
IndentWidth: 4
TabWidth: 4
UseTab: Never
ColumnLimit: 100
AllowShortBlocksOnASingleLine: false
AllowShortFunctionsOnASingleLine: None
BreakBeforeBraces: Attach
IncludeBlocks: Regroup
SortIncludes: CaseSensitive
```

Автоматическое форматирование всех файлов проекта перед коммитом:
```bash
clang-format -i src/*.cpp src/*.h
```
В VS Code включите в настройках `Editor: Format On Save` — и код будет форматироваться автоматически при каждом сохранении файла!

## 8. Включение санитайзеров (ASan и UBSan)

Санитайзеры внедряют диагностический код, который мгновенно роняет программу с понятным отчетом при выходе за пределы массива или переполнении.

Включить санитайзеры в CMake при отладке:
```cmake
# Внутри CMakeLists.txt для Debug сборки:
if (CMAKE_BUILD_TYPE STREQUAL "Debug")
    target_compile_options(my_program PRIVATE -fsanitize=address,undefined -fno-omit-frame-pointer)
    target_link_options(my_program PRIVATE -fsanitize=address,undefined)
endif()
```

Теперь при запуске `./build/my_program` любая ошибка работы с памятью вызовет не тихий сбой или мусорный вывод, а подробнейшую трассировку ошибки с указанием строчки кода!
